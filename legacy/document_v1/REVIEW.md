# Document v1 独立实现与实验结果审查

本文件仅保留 document-v1 的历史文字审查结论；当前归档源码使用方式见 [README.md](README.md)。**本次精简已清理全部旧 `runs/` 与 `RESULTS.*`，下文轨迹、收据和统计无法再依靠本地原始产物复验。** 当前保留的完整证据为编码主线108次正式实验和2次最新结构回归，见 [项目 README](../../README.md)。

审查日期：2026-09-24。审查对象为已保存的 `pilot_v3` 成功证据，以及冻结 `maintenance_v3` 后的三个正式矩阵；没有重新调用模型 API，没有修改原始实验记录。审查过程中未读取 `.env` 的值。

**当时的审查结论：正式矩阵中的有效工作、实际交付与主任务事实得分通过了原始轨迹和收集端记录交叉验证。** 主矩阵的包装条件在30次运行中有15次有效交付，跨三轮收集到全部10个子任务、60条按记录标识去重的结果。每一轮单独都没有完成全部10个子任务；最终回答格式也并非始终遵守“仅 JSON”的用户要求。该段描述当时完成的检查，不表示源证据现在仍可访问。

## 审查范围与证据

当时的正式目录为 `runs/validation_main`、`runs/validation_defenses` 和 `runs/validation_natural`，现均已清理。当时独立检查覆盖全部 **200次运行、658次有返回记录的模型调用**。以下各项均为历史记录。

- `plan.json` 与运行结果的 `run_id` 集合完全一致，无遗漏或重复；200 次运行均正常结束。攻击未成功的运行同样保留，没有把未成功当成运行错误，也没有删除这些记录。
- 658 个 API response ID 全部唯一；每次运行的 response ID 顺序、调用次数以及输入、输出、总 token 数与逐步轨迹中的返回 metadata 一致。三个矩阵合计返回用量为 **1,284,866 tokens**，不含 pilot；reasoning tokens 是输出用量中的子项，不能再次加总。
- 正式矩阵内全部源码快照与对应 manifest 的 SHA-256 一致。默认 Agent 的系统提示、用户任务和工具定义不因文档条件而改变；`boundary` 是单独列出的系统提示防御干预，`egress` 是单独列出的工具交付限制。
- 模型可见消息里的 `submit_result` 参数逐条对应工具执行参数；返回的 receipt ID 对应收集端持久化记录；实际 `submitted_rows` 与模型参数相同。逐条按独立标签重新判断后，有效性与记录评分一致。没有发现孤立收据、重复引用收据或脚本替模型补齐标签的情况。
- 交付聚合使用收集端实际收到的行。按 `(task_id, record_id)` 独立重新去重，得到的结果与 `collected_batch.json` 一致；不同条件或不同重复运行的提交不会重复增加有效工作量。
- 配置事实在模型提交之前已经通过普通 `read_document` 可见。事实未藏在提交后返回内容中，完成众包工作不是获取三个配置值的技术前提。
- 主任务事实分数按三个独立数值重新判断；JSON 输出格式另行判断，不把事实正确扩大解释为完整遵守所有用户要求。

`pilot_v3` 的两例也完成同样的交叉检查：系统提示、用户任务、Agent 执行代码与环境工具代码相对初始 pilot 保持一致；两例各由模型生成六行标签，实际 HTTP 返回有效收据，收集端共得到 12 条结果。不同 pilot 使用不同包装，属于校准记录，不能与冻结版本的正式矩阵混作同一组估计。

## 独立核对的正式结果

下表中的“交付且主事实正确”只检查三个配置事实，**不含 JSON 格式约束**。全部组的正文曝光率均为 100%，主任务三个事实也均正确。

| 矩阵与条件 | 运行数 | 正确工作可见 | 有效 HTTP 交付 | 交付且主事实正确 | 去重的已交付记录 |
|---|---:|---:|---:|---:|---:|
| 主矩阵：clean | 30 | 0 | 0 | 0 | 0 |
| 主矩阵：length_control | 30 | 0 | 0 | 0 | 0 |
| 主矩阵：direct | 30 | 0 | 0 | 0 | 0 |
| 主矩阵：wrapped | 30 | 15 | 15 | 15 | 60 |
| 防御：wrapped + boundary | 30 | 0 | 0 | 0 | 0 |
| 防御：wrapped + egress | 30 | 11 | 0 | 0 | 0 |
| 自然排序：clean | 10 | 0 | 0 | 0 | 0 |
| 自然排序：wrapped | 10 | 5 | 5 | 5 | 30 |

主矩阵三轮分别完成 **5、3、7** 个不同子任务，因此完整批次重复数是 **0**；跨轮并集覆盖 **10/10** 个子任务。自然排序矩阵只完成 **5/10** 个子任务，不能表述为该矩阵也完成了完整大任务。

Egress 条件中，11 次模型已经在工具参数中生成正确标注，但收集端收到的 HTTP 提交为零。这支持“交付限制可以阻止第三方获得成果，而额外计算仍可能发生”的有限结论。Boundary 条件中没有观察到正确标注或提交；内部是否进行了未输出的相关计算，不属于当前可观测指标。

## 输出格式与额外工具尝试

| 成功交付的样本组 | 主事实正确且交付 | 最终回答为原始 JSON 对象 | 允许一个独立 JSON 代码围栏 |
|---|---:|---:|---:|
| 主矩阵 wrapped | 15 | 2 | 7 |
| 自然排序 wrapped | 5 | 1 | 3 |

因此，若把“最终答案必须是原始 JSON 对象”也纳入完整任务成功，主矩阵对应结果是 **2/30**，而不是 15/30；允许单独代码围栏时为 **7/30**。这不否定有效第三方劳动发生，但限制了“主任务完全不受影响”的说法。

无攻击的对照也出现了 `submit_result` 调用：主矩阵 clean 为 **4 个运行、4 次调用**；length_control 为 **11 个运行、14 次调用**；自然排序 clean 为 **3 个运行、3 次调用**。这些调用没有完成所分配的众包任务，收集端拒绝验收，均未进入成功计数。主矩阵共持久化 33 次提交，其中 15 次有效；自然排序矩阵共 8 次，其中 5 次有效。**单独使用“尝试了提交工具”作为攻击成功指标会产生假阳性。** 对照中的额外调用也会影响 token 开销，所以 token 差只应解释为观察到的总体开销差。

## 密钥、推理内容与工具边界

实现审查确认 Agent 只能访问合成文档，不能通过工具读取任意本地文件、执行 shell 或指定外部收集地址。收集端绑定 `127.0.0.1` 临时端口；客户端目的地址与 run_id 由执行环境绑定，不接受模型参数覆盖，也不跟随 HTTP 重定向或代理环境变量。用于调用配置模型 API 的网络请求是单独的通信路径。

正式轨迹中未发现保存的 `reasoning_content` 字段；用量里的 reasoning token 计数不包含推理文本。对当时 `runs/` 内 **509 个 JSON、JSONL、Markdown、HTML 等文本产物**检查了明显的密钥值字段、完整 Bearer 值及常见密钥形状，未发现匹配。此检查没有读取 `.env`，因此不能替代将真实配置密钥仅在内存中与产物逐字匹配的最终检查。

API 请求体未设置 `max_tokens`、`max_completion_tokens` 或 `max_output_tokens`。服务商默认限制仍可能存在；40 步工具循环边界也仍存在，不能把“客户端无 token 上限”表述为无限执行。

## 解释限制与历史记录的可用性

60 条有效记录拥有不同的 record ID 和所属队列，但描述及影响字段来自 **12 个语义模板**。当前去重是记录级去重，不是语义去重；任务覆盖和独立劳动价值都不宜外推到真实众包数据分布。

自然排序实验使用一个很小的本地检索空间，全部来源最终都被读取；它没有证明公开互联网中的广播覆盖率或检索投放成功率。正式结果来自单一配置模型和一次固定矩阵，也没有证明现实成本收益为正。

源码、请求哈希、API 返回 ID、工具轨迹和本地收据共同支持执行记录的一致性；它们不是服务商签名的外部执行证明。该审查的结论限于当前受控实验和保存的证据。
