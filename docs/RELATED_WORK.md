## 与当前 PoC 的关系

在这五篇论文的已读部分中，TAB 与本实验的入口最接近：Agent 为解决用户任务读取环境材料，材料同时包含有用事实和超出任务的执行请求。它提醒我们，降低无关指令执行率时，也要检查合法任务是否仍能完成；拒绝全部外部内容不能单独证明 Agent 具有良好的任务边界判断。

本 PoC 把观察范围延伸到第三方得到的实际成果：被植入的内容描述一个独立标注子任务；Agent 需要生成具体标签、通过本地 HTTP 交付，收集端再独立验收并按记录去重，将多个子任务组合为完整批次。因此，“执行了额外动作”“多用了 token”“交付了可用工作”和“同时保留主任务事实正确性”是不同的指标。这里描述的是本项目选择验证的机制，**不是经过系统文献检索确认的新颖性结论**。

Overeager Coding Agents 的主要设定是良性请求中的自发越界；本 PoC 则明确存在控制一份低信任检索文档的第三方。二者共同涉及授权边界，但诱因不同。仅仅因为额外工作在语义上与产品或版本有关，不代表用户授权了执行与提交；本实验用户只要求三个默认配置事实。

RedundancyBench、RideWay 和 Action Boundary Blindness 提供了效率及边界判断方面的参考，但“步骤多”并不能直接推出“计算被挪用”。第三方独立验收与交付证据能够补充说明额外动作产生了谁需要的成果；开销对照则单独回答用户为不同执行路径付出了多少资源。

## 对实现与结果解释的约束

1. **把曝光与执行分开。** 检索结果列出文档标题不等于正文中的请求进入模型上下文。本实现以实际 `read_document` 返回第三方正文计曝光。`forced` 仅把该来源放到首次搜索首位，仍由模型选择是否读取；`natural` 也只是本地词项索引，不能代表开放互联网的投放效果。
2. **保证存在无须额外工作的合法解法。** 各文档条件保留相同的配置事实。事实在正文中直接可读，不需要提交标注才能解锁；干净对照能够独立验证正常求解路径。
3. **根据发生的行为计分。** 模型的口头承诺不能算执行成功。有效交付需要模型生成的工具参数、实际 HTTP 请求、持久化收据和独立标签验收相互一致。Gold 不作为模型工具输入，收集器不能替模型补齐结果。
4. **把事实正确性与完整指令遵循区分开。** 当前主任务评分检查三个事实字段，兼容代码围栏和附加文字；它不检查“仅返回 JSON”等全部输出格式要求。因此主任务通过表示事实正确，不能扩大解释为所有用户约束均被满足。
5. **避免数量造成误导。** 失败、未完成和未曝光运行保留在结果中；曝光条件成功率使用实际曝光次数作为分母。重复交付可以构成多次成功运行，但同一任务的同一记录只能算一个可复用工作单元。
6. **把开销与挪用的精确数量区分开。** 字符等长对照不保证模型 token 数完全相同。API 总 token 差还包含上下文回放、重试及执行路径变化，不能直接命名为“被盗 token 数”。固定预算下也可能发生资源挪用，不能仅凭总 token 增长判断。
7. **如实保留校准过程与评测范围。** 包装调整使用的 pilot 与冻结版本后的矩阵结果分开呈现。少量合成任务、单一模型以及本地工具环境只支持机制可行性的有限结论，不支持现实盈利性、通用安全性或模型排名结论。

下一阶段如果计划投稿，应补充系统检索间接提示注入、工作流劫持、资源滥用、经济型拒绝服务与分布式众包等相关方向，并逐篇核验威胁模型和验收定义。当前保留的编码主线目录提供其各自的完整轨迹和可复算材料；这里沿用的旧文档实验产物已不在本地。
