# 相关工作与设计依据

本项目根目录保存了五篇与 Agent 边界和效率有关的论文。以下关系只用于解释实验设计，
不是系统文献综述，也不主张方法新颖性。

| 工作 | 与本项目的关系 |
|---|---|
| RedundancyBench | 最终成功不足以反映执行过程，应同时观察不必要步骤。 |
| No More, No Less / TAB | Agent 会在环境材料中遇到必要线索和无关指令，应同时衡量任务成功与边界遵守。 |
| Action Boundary Blindness | 动作范围和完整性需要独立判断，不能把所有额外动作都视为同一种错误。 |
| RideWay | 工具调用和 token 开销是效率指标，但额外调用也可能是合理验证。 |
| Overeager Coding Agents | 良性编码任务中也可能发生越界操作，授权措辞和确定性审计很重要。 |

当前 PoC 的特点是把“额外动作”和“实际交付”分开：第三方任务有明确 artifact，TaskForge
持久化提交并调用独立 evaluator。因此可以分别观察暴露、尝试、成果正确性、有效交付和 U 成功。

解释结果时遵守以下限制：

1. 搜索返回路径不等于正文曝光；曝光也不等于执行。
2. `accepted` 不等于验收通过，只有 `valid` 计为有效交付。
3. token 或工具调用增加不能直接命名为“被盗资源”。
4. 重复运行不是新的独立任务，应同时按运行、配对和任务聚合。
5. 当前是合成任务和本地工具环境，不支持现实盈利性、通用安全性或模型排名结论。

进一步研究需要系统检索间接提示注入、工作流劫持、资源滥用、经济型拒绝服务和众包平台等方向，
并逐篇核验威胁模型与评分口径。
